# YouTube 美容トレンドリサーチ

美容領域の YouTube 動画のうち「いま伸びているもの」を毎朝自動で集めて、
ブラウザで一覧できるようにするツールです。サーバーもデータベースも使いません。

- 収集：GitHub Actions が毎日 朝6時（日本時間）に自動で走ります
- 保存：結果は `docs/data/videos.json` としてリポジトリにコミットされます
- 表示：GitHub Pages の URL を開くと一覧が見られます

一覧では、次のことができます。

- 並び替え（伸びの速さ／加速度／再生数／登録者比／新着順）
- 絞り込み（公開日・主ジャンル・掛け合わせ語・ショート/通常・登録者数の上限・フリーワード）
- 表示中の結果を CSV で保存

## 0. まずやること：GitHub にリポジトリを作る

この一式はまだ手元のフォルダにあるだけです。GitHub に上げると自動収集が動き出します。

1. [github.com/new](https://github.com/new) を開く
2. **Repository name** に `youtube-beauty-trends` と入れる
3. 公開範囲を選ぶ
   - **Public**（公開）… GitHub Pages が無料で使えます。**こちらを推奨**
   - **Private**（非公開）… Pages を使うには有料プランが必要です
4. 他は触らずに **Create repository** を押す
   （README や .gitignore を追加するチェックは**入れない**でください）
5. ターミナルで次を実行する（`<ユーザー名>` は自分のものに置き換える）

```bash
cd ~/Projects/youtube-beauty-trends

git init -b main
git add .
git commit -m "初回コミット: YouTube 美容トレンドリサーチツール"
git remote add origin https://github.com/<ユーザー名>/youtube-beauty-trends.git
git push -u origin main
```

これで GitHub 上にファイルが並びます。続けて手順1〜3を行ってください。

> `docs/data`（収集結果の置き場）はまだありません。手順5で初回の収集を走らせると作られます。
> 手元で画面だけ先に見たいときは `python3 collector/collect.py --mock` でサンプルを作れますが、
> **その状態で push しないでください**（本物の数字ではないため）。
> 万一混ざっても画面に「これはサンプルデータです」と赤枠で出て、次の収集で本物に置き換わります。

## 1. セットアップ①：YouTube の API キーを取る

YouTube のデータを取るには「API キー」という文字列が要ります。無料です。

1. ブラウザで [Google Cloud Console](https://console.cloud.google.com/) を開き、
   Google アカウントでログインする
2. 画面いちばん上の、Google Cloud ロゴの右にあるプロジェクト選択（初回は
   「プロジェクトを選択」と出ている）を押す → 右上の **新しいプロジェクト** を押す
3. プロジェクト名に `youtube-beauty-trends` などと入れて **作成** を押す。
   作成が終わったら、もう一度上のプロジェクト選択から、いま作ったものを選ぶ
4. 左上のハンバーガーメニュー（横三本線）→ **API とサービス** → **ライブラリ** を開く
5. 検索欄に `YouTube Data API v3` と入れて、出てきたものを押す →
   青い **有効にする** ボタンを押す
6. 左メニューの **認証情報** を開く → 画面上の **＋ 認証情報を作成** →
   **API キー** を選ぶ
7. `AIza…` で始まる文字列が表示される。これが API キー。
   **閉じる前にコピーしておく**（後からでも認証情報の一覧から見られます）

> **API キーは人に見せないでください。** このリポジトリのコードに書き込むのも禁止です。
> 次の手順で GitHub の金庫（Secrets）に預けます。

**（推奨）キーに制限をかける**
認証情報の一覧でいま作ったキーの名前を押し、
「API の制限」で **キーを制限** を選び、`YouTube Data API v3` だけにチェックを入れて保存します。
万一キーが漏れても、他のサービスには使えなくなります。

## 2. セットアップ②：API キーを GitHub に登録する

1. GitHub でこのリポジトリのページを開く
2. 上のタブの **Settings**（設定）を押す
3. 左メニューの **Secrets and variables** → **Actions** を押す
4. 緑の **New repository secret** ボタンを押す
5. 次のとおり入力して **Add secret** を押す
   - **Name**（名前）: `YOUTUBE_API_KEY` … 大文字・アンダースコアまで正確に
   - **Secret**（値）: 手順1でコピーした `AIza…` の文字列
6. 一覧に `YOUTUBE_API_KEY` が並べば完了。値は登録後は二度と表示されません
   （見えなくて正常です）

## 3. セットアップ③：GitHub Pages を有効にする

1. リポジトリの **Settings** を押す
2. 左メニューの **Pages** を押す
3. **Source**（ソース）で **Deploy from a branch** を選ぶ
4. **Branch** で `main`、その右のフォルダで **`/docs`** を選び、**Save** を押す
5. 1〜2分待ってページを再読み込みすると、上部に公開 URL が出る

   ```
   https://<あなたのGitHubユーザー名>.github.io/youtube-beauty-trends/
   ```

この URL がリサーチツールの入口です。ブックマークしてください。

> 最初は「データを読み込めませんでした」と出ます。まだ1回も収集が走っていないためです。
> [手順5](#5-今すぐ手動で収集する) で1回走らせると表示されます。

## 4. キーワードを追加・変更する

検索する語は [`collector/keywords.yml`](collector/keywords.yml) にまとまっています。
Threads / Instagram のリサーチツールと同じ構成です。

- **主ジャンル（12）** … 単独で検索して意味が通る語。1ジャンル1語
- **掛け合わせ語（6）** … 単独では検索しない語

「経営」「メニュー」を単独で検索すると、飲食店や一般ビジネスの動画を大量に拾います
（Threads 版の実測で31件中23件＝74%が無関係でした）。そこで掛け合わせ語は単独では検索せず、
`modifiers` に並べた主ジャンルと組ませた語だけを検索します。
YouTube の検索は空白がANDなので、組ませるだけで絞り込めます。

```
エステティシャン 経営     ← 検索する
ヘッドスパ メニュー       ← 検索する
経営                      ← 検索しない
```

### 編集のしかた

1. GitHub でリポジトリを開き、`collector` → `keywords.yml` を押す
2. 右上の鉛筆マーク（Edit this file）を押す
3. 書き換える
4. 画面下の **Commit changes** を押す

```yaml
genres:
  ヘッドスパ:
    - ヘッドスパ          # 空白2つ＋4つのインデントを守る

modifiers:
  経営:
    - ヘッドスパ          # 「ヘッドスパ 経営」で検索される
    - エステティシャン    # 「エステティシャン 経営」で検索される
```

- 主ジャンルを足す：`genres:` の下に「（空白2つ）ジャンル名:」と「（空白4つ）- 検索語」
- 掛け合わせを足す：`modifiers:` の下に「（空白2つ）語:」と「（空白4つ）- 組ませる主ジャンル名」
- 一時的に止めたい行は、行頭に `#` を付ければ検索されなくなります

**消費ユニットへの影響**

| | 検索回数 | 消費ユニット |
|---|---|---|
| 主ジャンルを1つ足す | +1 と、組ませる掛け合わせの数だけ増える | +100 × その数 |
| 掛け合わせを1つ足す | 組ませる主ジャンルの数だけ増える | +100 × その数 |

いまは53語（5,300ユニット）です。**60語を超えた分はその日は検索されず、翌日以降に回ります**
（日替わりローテーション）。上限は1日10,000ユニットです。

### カテゴリ名を変えたとき

主ジャンル名や掛け合わせ語を変えると、それ以前に集めた動画には古い名前が付いたままになります。
扱いは次のとおりです。

- 収集が正常に終わると `videos.json` は毎回作り直されるので、**古い名前は自動的に消えます**
- クォータ切れで前回分を持ち越すときは、**辞書に無い名前をその場で取り除きます**。
  主ジャンルが1つも残らない動画は、いまの関心から外れた動画なので持ち越しません
- `docs/data/history/` は再生数の比較にしか使わないので、古い名前が画面に出ることはありません

## 5. 今すぐ手動で収集する

毎朝6時を待たずに走らせられます。キーワードを変えた直後の確認にも使ってください。

1. リポジトリの **Actions** タブを押す
2. 左の一覧から **収集** を押す
3. 右側の **Run workflow** ボタンを押す → もう一度 **Run workflow** を押す
4. 1〜3分で終わります。緑のチェックが付けば成功
5. Pages の URL を開き直すと、新しいデータが反映されています

うまくいったか確かめたいときは、実行結果を押して「収集を実行」のログを開くと、
何件取れたか・何ユニット使ったかが出ています。

## 6. よくあるトラブル

### ページが「データを読み込めませんでした」と出る

まだ1回も収集が成功していない状態です。[手順5](#5-今すぐ手動で収集する) で
手動実行してください。それでも直らない場合は Actions のログを確認します。

### Actions が赤い×で失敗する

ログを開いて、最後の赤い行を見ます。よくある原因は次の2つです。

- `環境変数 YOUTUBE_API_KEY が設定されていません`
  → [手順2](#2-セットアップapi-キーを-github-に登録する) の名前が
  `YOUTUBE_API_KEY` と一致しているか確認する
- `API key not valid` / `403`
  → Google Cloud 側で YouTube Data API v3 が有効になっているか、
  キーの制限が厳しすぎないかを確認する

### ログに「クォータ超過」と出た

1日に使える量（10,000ユニット）を使い切ると出ます。**放置して構いません。**
翌日の日本時間17時ごろに枠が戻り、次の実行から通常どおり集まります。
このとき、それまでに集めたデータは壊れません。

頻発する場合は、`keywords.yml` の語を減らすか、手動実行の回数を減らしてください。
現在の53語なら1回あたり最大5,406ユニットなので、1日1回の自動実行に手動実行を1回足せる程度です。

### Pages の URL が 404 になる

- [手順3](#3-セットアップgithub-pages-を有効にする) でフォルダが `/docs` に
  なっているか確認する（`/(root)` だと表示されません）
- 設定直後は反映に数分かかります
- URL の末尾のスラッシュ（`/youtube-beauty-trends/`）を省くと 404 になることがあります

### 一覧に古い動画ばかり出る

画面上部の **公開日** で「7日以内」を選ぶと直近のものだけになります。
並び替えを **加速度（直近の伸び）** にすると、いま伸びている動画が上に来ます。
加速度は前日との比較なので、収集2日目以降から値が入ります。

### 大手メディアの動画ばかりで参考にならない

**登録者数** を「1万人以下」などに絞ると、自分と近い規模のチャンネルだけになります。
並び替えを **登録者比** にすると、登録者数のわりに跳ねた動画が上に来ます。

## 7. 開発者向けメモ

### ローカルで動かす

```bash
# APIキー無しでサンプルデータを作る（画面の確認用）
python3 collector/collect.py --mock

# 本番。キーを使うので消費ユニットが発生する
export YOUTUBE_API_KEY="AIza..."
python3 collector/collect.py

# キーワード3語だけで試す（300ユニットで済む）
python3 collector/collect.py --limit 3
```

画面は `docs/` を静的配信して開きます。

```bash
python3 -m http.server 8000 --directory docs
# → http://localhost:8000/
```

`file://` で直接開くと、ブラウザの制限で `videos.json` を読めません。必ずサーバー経由で開いてください。

### テスト

```bash
python3 collector/collect.py --mock   # 先にサンプルデータを作る
python3 tests/verify_collector.py     # 収集側 85項目
node tests/verify_app.mjs             # 画面側 65項目
```

- `verify_collector.py`：長さの解釈、キーワード辞書（Threads版の設定と直接照合）、
  検索プランの組み立て、日替わりローテーション、クォータ集計、APIレスポンスの変換、
  スコア計算、履歴の掃除、辞書から消えたカテゴリ名の扱い、クォータ超過時の挙動
- `verify_app.mjs`：2段フィルタのAND/OR、0件チップ、絞り込み、並び替え、CSV、
  HTMLエスケープ、データが読めないとき
  （jsdom は `salon-karte` の `node_modules` を借りています）

どちらも見た目・改行位置までは見ていません。デザインの確認はブラウザで目視してください。

### 構成

```
.github/workflows/collect.yml  cron 実行 + 自動コミット
collector/
  collect.py                   収集の本体
  keywords.yml                 キーワード辞書
  scoring.py                   スコア計算
  requirements.txt
docs/                          GitHub Pages の公開ディレクトリ
  index.html / app.js / style.css
  data/videos.json             最新の一覧（画面が読む）
  data/history/YYYY-MM-DD.json 日次スナップショット（30日で自動削除）
tests/verify_app.mjs           画面の自動テスト
```

`data/` を `docs/` の下に置いているのは、GitHub Pages が `docs/` の中身しか配信しないためです。
リポジトリ直下の `data/` に置くと、画面から読み込めません。

### スコアの定義

| 指標 | 計算 | 見たいもの |
|---|---|---|
| 伸びの速さ `velocity` | 再生数 ÷ 公開からの経過日数 | ならして強い動画 |
| 加速度 `acceleration` | (今回の再生数 − 前回の再生数) ÷ 前回からの経過日数 | いま伸びている動画 |
| 登録者比 `subRatio` | 再生数 ÷ 登録者数 | 小さいチャンネルの跳ねた動画 |

前回データが無い動画の加速度は空欄です（0 ではありません）。

### 保存しないもの

動画の説明文とコメント本文は保存していません。タイトル・統計値・メタ情報だけを扱います。
`docs/data/history/` は30日を超えたものを収集のたびに削除します。
